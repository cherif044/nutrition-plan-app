2. Refactor Rules
Do NOT change any business logic or behavior.
Only restructure code into proper layers.
Split files if they contain multiple responsibilities (one file = one clear responsibility).
Ensure correct separation:
routes → define endpoints only
controllers → request/response handling only
services → ALL business logic (core system logic lives here)
repositories → data access (JSON/DB/files)
middleware → auth, validation, permissions
utils → helper functions only
Avoid overengineering, keep it clean and minimal.
If something is unclear, choose the simplest correct architecture decision.

macro splitting (protein, fat, carbs)

food selection from dataset

rebalancing when constraints are not met
