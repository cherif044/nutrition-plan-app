Goal:
Keep the optimizer architecture, but fix these issues:

1. Add warning/error severity classification.

Currently huge failures are being reported as warnings. That is wrong.

Implement a clear severity system:

A. PASS:
The generated plan is within tolerances.

B. WARNING:
The plan is close enough to be usable but approximate.
Examples:

* calories off by a small amount
* protein short by a small amount
* fat/carbs slightly outside tolerance
* selected templates hit serving bounds but final output is still reasonably close

C. HARD ERROR / IMPOSSIBLE:
The plan is structurally infeasible with the current templates and restrictions.
Examples:

* required main meal slots have no feasible templates
* actual calories are far below target
* protein is far below target
* the plan only contains snack/coffee/milk calories while meals are missing
* vegan/avoid-food restrictions remove all useful templates
* 2-meal/Ramadan targets cannot be reached because templates hit serving bounds badly

Suggested thresholds:

* If actual calories < 80% of target calories, mark as hard error.
* If actual calories < 70% of target calories, definitely hard error.
* If protein is short by more than max(25g, 20% of target protein), hard error.
* If any required main meal slot has no feasible template, hard error.
* If more than one required main meal slot is missing, hard error.
* If the plan has fewer generated meals than requested because no feasible templates exist, hard error.
* If only snack/coffee/milk calories exist and main meals are missing, hard error.
* Small deviations remain warnings, not errors.

Use named constants in nutritionConstants.js for these thresholds so they are tunable.

2. Return useful impossible-plan diagnostics.

When hard error happens, the response should clearly explain:

* which macro(s) are badly short/over
* which meal slots had no feasible templates
* whether the issue is template coverage, serving bounds, or restrictions
* which restrictions likely caused the failure

Examples:

* "Impossible with current templates: no feasible vegan templates for Breakfast, Lunch, Dinner."
* "Protein remains short by 144g because current vegan templates do not include enough high-protein main meals."
* "2-meal layout cannot reach 2400 kcal because selected templates hit serving bounds."
* "Avoiding chicken, dairy, and nuts removes too many high-protein/high-calorie templates."

Do not blame calorie slot ranges if the real issue is missing templates or macro-density.

3. Fix the suspicious carb residual percentage.

The test summary reported:
worst carb residual: 16674.2%

Investigate this. It may be caused by:

* dividing by a tiny or zero carb target
* using wrong denominator
* treating grams as percent incorrectly
* using residual percentage where normalized score should be used

Fix the reporting so residual percentages are meaningful.

Rules:

* residual percent should be abs(actual - target) / target * 100
* if target is zero or near-zero, do not produce absurd percentages; report as N/A or use an absolute residual instead
* do not let this affect plan scoring incorrectly

Add tests for this calculation.

4. Improve 2-meal and Ramadan edge handling without adding templates.

Do not add templates.

But improve diagnosis and behavior when selected templates hit bounds.

For 2-meal layouts:

* each meal has a larger calorie requirement
* if templates cannot scale enough due to min/max serving bounds, classify correctly
* if close enough, warning is okay
* if far below target, hard error with serving-bounds diagnosis

For Ramadan split:

* preserve existing Ramadan behavior
* if iftar/suhoor-style slots cannot reach targets due to serving bounds or missing templates, diagnose clearly
* do not silently return a very low-calorie plan as warning

5. Missing slot handling.

* record the missing slot
* do not pretend the plan is valid
* include missing slot names in warnings/errors
* hard error if missing required main slots cause major macro/calorie shortfall

Coffee/milk/snacks should not hide the fact that main meals are missing.
